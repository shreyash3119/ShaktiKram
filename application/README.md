# ShaktiKram app (Android)

Flutter app for the ShaktiKram personal fitness system. Android only for now (decision F1).
Architecture and rules: `../docs/FLUTTER_ARCHITECTURE.md`.

## First-time setup

The Android platform folder is generated by Flutter itself (already done if you ran step 1):

```
cd application
flutter create --platforms=android --project-name shaktikram --org com.shaktikram .
```

If it replaces any Dart file from this repo, restore that file from git. Delete the default `test/widget_test.dart`.

### Connect the app to your Supabase project (step 2)

1. In the Supabase dashboard, open Project Settings, then API. Copy the **Project URL** and the **anon / publishable key**.
   Never use the `service_role` or `sb_secret_` key. The app refuses to start if it finds one.
2. Copy `dart_defines.example.json` to `dart_defines.json` and fill in the two values.
   Add `application/dart_defines.json` to the root `.gitignore` so it is never committed.
3. Create the owner account once: Authentication, Users, Add user. Enter email and password and tick auto-confirm.
   Sign-ups must stay switched off (decision D3). The app has no registration screen.
4. Release builds need internet permission. Check `android/app/src/main/AndroidManifest.xml` and add this line
   inside `<manifest>`, above `<application>`, if it is missing (debug builds already have it):
   `<uses-permission android:name="android.permission.INTERNET"/>`

### Run and check

```
flutter pub get
flutter analyze
flutter test
flutter run --dart-define-from-file=dart_defines.json
```

Package versions in `pubspec.yaml` are minimum floors. `flutter pub upgrade` takes the newest compatible ones.

## How sign-in works (step 2)

1. First launch: the sign-in screen asks for the owner email, password and a name for this phone.
2. After signing in, the app calls `api_claim_owner` (safe to repeat) and `api_register_device`, then opens Home.
3. Later launches open straight to Home, **even with no internet**. Nothing is asked of the server until it is needed.
4. Settings shows the account and this device. Manage devices lists every registered device and can remove the others.
5. If this device is removed from another phone, the app shows a "This device was removed" screen.
6. Sign out is in Settings.

Removing a device blocks its writes and pulls at once, but its sign-in stays valid until the access token expires
(up to one hour). For a lost phone, also sign out all sessions and change the password in the Supabase dashboard.

## What works

- Step 1: six-section navigation, placeholder theme, sync indicator (stub), dashboard skeleton, shared state views.
- Step 2: owner sign-in, session kept across launches, offline start, device registration, devices list and removal,
  sign out, startup screens for a missing or unsafe configuration.

## Folder layout

```
lib/
  main.dart, app.dart
  core/
    config/    build-time settings and the key safety check
    backend/   BackendGateway (the server calls the app uses) and the Supabase implementation
    auth/      sign-in service, device store, session controller (the sign-in state machine)
    routing/   routes, bottom navigation, redirect by session state
    sync/      sync status (stub until step 3)
    theme/, widgets/
  features/    one folder per section, plus auth/ for the sign-in screens
test/
  support/fakes.dart   fake auth, fake gateway, in-memory device store
```

Only `core/auth/supabase_auth_service.dart`, `core/backend/supabase_backend_gateway.dart` and `main.dart` import Supabase.
Everything else, including the tests, uses the interfaces.
